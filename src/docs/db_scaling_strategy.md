# Стратегия масштабирования БД для проекта SFMShop

## Репликация

### Когда использовать:
- Высокая нагрузка на чтение
- Нужна отказоустойчивость
- Простое масштабирование

### Отказоустойчивость. Масштабирование чтения. Проще в настройке.
### Недостатки:
- Задержка репликации
- Не масштабирует запись
- Требует больше места

### Примеры для SFMShop:
- Чтение списка товаров - из реплики
- Чтение заказов пользователя - из реплики
- Создание заказа - в основную БД

## Шардирование

### Когда использовать:
- Очень большие объемы данных
- Нужно масштабировать запись
- Данные можно разделить по ключу

### Масштабирование записи. Распределение данных. Горизонтальное масштабирование.
### Недостатки:
- Сложность в настройке
- Сложные JOIN запросы
- Неравномерное распределение

### Примеры для SFMShop:
- Шардирование по user_id для заказов
- Шардирование по product_id для товаров
- Hash sharding для равномерного распределения

## Компромиссы

### Eventual Consistency:
- Данные в репликах могут быть не синхронны
- Приемлемо для чтения
- Неприемлемо для критических операций

### Рекомендации:
- Использовать репликацию для начала
- Переходить на шардирование при необходимости
- Мониторить производительность
