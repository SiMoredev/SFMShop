# Архитектура баз данных для проекта SFMShop

## Общая схема

┌─────────────┐

│ PostgreSQL │ ← Основные данные (users, products, orders)

└─────────────┘

│

├─→ Запись основных данных

└─→ Чтение основных данных

┌─────────────┐

│ Redis │ ← Кэш, сессии, очереди

└─────────────┘

│

├─→ Кэш товаров

├─→ Сессии пользователей

└─→ Очереди задач

┌─────────────┐

│ MongoDB │ ← Логи, аналитика, события

└─────────────┘

│

├─→ Логи приложения

├─→ Аналитические данные

└─→ События пользователей

## Распределение данных

### PostgreSQL
- **users** - пользователи
- **products** - товары
- **orders** - заказы
- **order_items** - элементы заказов
- **reviews** - отзывы

**Причины:**
- Структурированные данные
- ACID транзакции
- Связи между данными

### Redis
- **cache:products:all** - кэш списка товаров
- **cache:product:{id}** - кэш товара
- **session:{token}** - сессии пользователей
- **queue:tasks** - очереди задач

**Причины:**
- Высокая скорость
- TTL для автоматического удаления
- Временные данные

### MongoDB
- **logs** - логи приложения
- **analytics** - аналитические данные
- **events** - события пользователей

**Причины:**
- Гибкая структура
- Масштабируемость
- Аналитические запросы

## Поток данных

1. **Запрос товаров:**
   - Проверка кэша в Redis
   - Если нет - запрос к PostgreSQL
   - Сохранение в кэш Redis

2. **Создание заказа:**
   - Запись в PostgreSQL (транзакция)
   - Инвалидация кэша в Redis
   - Логирование в MongoDB

3. **Аутентификация:**
   - Проверка в PostgreSQL
   - Создание сессии в Redis
   - Логирование в MongoDB
